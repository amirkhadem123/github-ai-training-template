# Exercise 5 — Capstone: Upcoming Milestones

Complete this exercise without step-by-step implementation instructions.

## Requirement

Stakeholders want the weekly update to include an **Upcoming Milestones** section.

It should show milestones due within the next **30 days** from a configurable report date.

For each matching milestone, show:

- project;
- milestone;
- owner;
- due date.

The implementation should keep the starter project simple and dependency-free.

## Your workflow

Independently:

1. make sure your repository is current;
2. create an appropriate branch;
3. give the AI the requirement and relevant context;
4. ask it to inspect before changing;
5. request an implementation plan;
6. review the proposed scope;
7. allow implementation;
8. run and validate the workflow;
9. review changed files;
10. create a meaningful commit;
11. push the branch;
12. open a pull request.

## Pull request description

Include:

### Why

What requirement does this address?

### What changed

Describe the result in plain language.

### Validation

How did you verify it?

### Review notes

Is there anything you would want a more technical teammate to examine?

## Success

You do not need to explain the Python syntax.

You should be able to explain:

- the business requirement;
- which parts of the project changed;
- how you validated the result;
- how the work moved from your computer to GitHub;
- whether additional technical review is appropriate.
