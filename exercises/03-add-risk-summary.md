# Exercise 3 — Add a Risks Section

## Scenario

The weekly project update is useful, but stakeholders want important risks to be easier to see.

## Requirement

Add a **Risks** section to the generated report.

The section should list projects where:

- `priority` is **High**; and
- `status` is either **At Risk** or **Blocked**.

For each matching project, show:

- project name;
- owner;
- status;
- notes.

## Required workflow

1. Make sure your local repository is current.
2. Create a new branch for this requirement.
3. Ask your AI assistant to inspect the repository and requirement.
4. Ask for a plan before implementation.
5. Review the expected file changes.
6. Approve a small, reasonable implementation.
7. Run the workflow.
8. Inspect the generated output.
9. Review the changed files in GitHub Desktop.
10. Commit and push your branch.
11. Open a pull request into your own `main` branch.

## Suggested planning prompt

> Review this repository and the requirement to add a Risks section. Propose the smallest reasonable implementation. Tell me which files you expect to change and how you will validate the result. Do not implement anything yet.

## Definition of done

The report includes a clearly labeled Risks section containing the three high-priority problem projects from the sample data.
